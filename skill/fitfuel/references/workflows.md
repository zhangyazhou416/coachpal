# 典型工作流

## 1. 首次建档

按顺序补齐，避免一次问太多：

1. `profile show` 看已有信息。
2. 只问缺的：性别、出生年份、身高、活动水平、目标（减脂/维持/增肌）。
3. 写入 `profile set`。
4. `weight add` 记录当前体重；有条件再记体脂率、骨骼肌量。
5. 量一次围度（胸/腰/臀/上臂/大腿），写入 `measure add`。
6. 设置 1-2 个目标，不要一次设五个：`goal set weight 72 --date ...`、`goal set waist 80`。
7. 可选：记录最近一次力量训练作为起点，`strength add` 或 `workout add`。

完成后给用户一个简短摘要：当前 BMI、目标、每日热量/蛋白质目标。

## 2. 每日体重

用户说“今天 77.9，体脂 21.4”：

```bash
python3 -m fitfuel --json weight add 77.9 --body-fat 21.4
```

- 同一天重复记录会合并，不会产生两条。
- 如果用户只报体重，不要追问体脂；体成分不是每天都需要。
- 回复：记录值 + 与最近一次/7 日均值的差。不要对单日波动做过度解读。

## 3. 饮食记录

用户说“午饭吃了 150g 鸡胸肉、200g 米饭、一份西兰花”：

1. 先 `food search` 或直接 `meal add --item`。
2. 如果返回歧义（如鸡胸肉 → 鸡胸脯肉/火鸡胸脯肉），把候选列出来让用户确认。
3. 确认后一次性写入这一餐。
4. 回复解析后的真实食物名、克数、热量、蛋白/脂肪/碳水，以及今日 totals 与剩余。

常见份量需要确认：

- “一碗米饭”约 150-200 g 熟重；“一勺蛋白粉”约 25-30 g；“一个鸡蛋”约 50 g 可食部。
- 外卖、菜谱、复合食品通常不在成分表里，用 `--custom`，并明确说“按你给的信息估算”。

### 食物库没有时

```bash
python3 -m fitfuel --json meal add --type 加餐 \
  --custom "蛋白粉:30:120:24:1.5:3"
```

格式：`名称:克数:热量:蛋白:脂肪:碳水[:纤维]`，数值是**这一份的总量**，不是每 100 g。

### 多餐一次说

用户一次报三餐时，逐餐调用 `meal add`，每餐保留独立 id，方便之后删除/修正。不要合并成一餐。

## 4. 训练记录

用户说“今天推日：卧推 80 做了 5 组 5 次，RPE8；高位下拉 60 做 3 组 10 次”：

```bash
python3 -m fitfuel --json workout add --name 推日 \
  --set "卧推 80 5 @8" --set "卧推 80 5 @8" --set "卧推 80 5 @8" --set "卧推 80 5 @8" --set "卧推 80 5 @8" \
  --set "高位下拉 60 10 @8" --set "高位下拉 60 10 @8" --set "高位下拉 60 10 @8"
```

- 同一动作重复写多次即可，组号自动递增。
- RPE 可省略；有 RPE 时保留，便于以后分析强度。
- 如果用户只想记录“三大项”，用 `strength add` 更轻量，便于追踪 1RM 和 PR。
- 回复：动作数、组数、总训练量、是否有新 PR。不要对一次训练做过度评价。

## 5. 周复盘

```bash
python3 -m fitfuel --json report --days 7
```

按这个顺序解读：

1. **记录质量**：饮食记录几天？训练几次？记录太少先别下结论。
2. **体重趋势**：与目标方向是否一致；单周波动不急着改热量。
3. **饮食**：平均热量 vs 目标、蛋白质是否接近目标、记录天数。
4. **训练**：训练量/次数 vs 前几周；是否有 PR。
5. **只给一个调整**：例如“蛋白质每天再加 20 g”或“下周把训练量提高 5%”，不要同时改五件事。

常见判断：

- 减脂 2-3 周体重不降、腰围不降、记录完整 → 可考虑热量下调 5-10% 或增加日常活动，而不是直接砍到 1200 kcal。
- 增肌体重每周涨超过 0.5-0.7 kg 且腰围明显上升 → 热量略降。
- 训练量骤降、睡眠差、持续疲劳 → 先安排减载周，不要加码。

## 6. 目标调整

- 目标应具体、可测、有日期：体重 72 kg、腰围 80 cm、卧推 100 kg。
- 达成后运行 `goal list` 确认；然后归档旧目标或设新目标。
- 目标方向与当前趋势相反时（减脂期设增肌目标），先和用户确认优先级。
- 不要设“一个月减 10 kg”这类不现实目标；用每周 0.5-1% 体重的速度做参考。

## 7. 看板

```bash
python3 -m fitfuel dashboard --days 90 --open
```

看板适合用户自己想看趋势时使用：

- 30/90/365/全部切换。
- 体重/体脂、围度小图、1RM、每日热量、每周训练量、目标进度、最近训练。
- 每个图都有悬浮提示和数据表；深色模式可切换。

如果用户说“图上看不到数据”，先检查对应记录是否存在、日期是否在范围内。

## 8. 数据维护

- 数据库：`data/fitfuel.db`；看板：`data/dashboard.html`。都已被 `.gitignore` 排除。
- 备份：直接复制 `data/fitfuel.db` 即可（先停止写入）。
- 食物/动作库可随时重新 `seed`，不会删除个人记录。
- 不要手动编辑 SQLite；需要改记录用 CLI（`meal delete`、`workout delete`）或让用户确认后再操作。
- 用户换电脑时，复制数据库 + 重新 `seed` 即可。
